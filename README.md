# Transaction Report Parser & Consolidator

A Python ETL pipeline that parses raw daily transaction reports from multiple payment networks — each with a different file format — enriches every record with a provider lookup, applies a fee schedule, and exports a single consolidated, formatted Excel report.

> **Note:** This project is inspired by real-world payment reconciliation work I do as a data analyst in the Indonesian banking industry. All file formats, provider names, fee values, and transaction data in this repository are **fictional**, generated by the included sample data script. No proprietary code or data is used.

## The Problem

Operations teams often receive daily transaction report files from multiple switching networks, each with its own format:

- **Network Alpha** delivers pipe-delimited `.raw` files
- **Network Beta** delivers fixed-width `.txt` files with positional columns

Consolidating these manually in Excel — filtering declined transactions, mapping each terminal to its managing provider, and applying the correct fee per provider — takes hours per day and is error-prone: a single wrong column position or a missed terminal prefix silently corrupts the reconciliation numbers.

## The Solution

A single command parses every file in the input folder, regardless of format:

```
python parse_transactions.py
```

The pipeline:

1. **Auto-detects file format** by filename pattern and routes each file to the right reader (pipe-delimited vs fixed-width positional parsing)
2. **Filters by response code** (default `51` — insufficient funds; configurable via `--rc`, or `--rc all` to keep everything)
3. **Enriches each record** by matching the 4-digit terminal ID prefix against `terminal_lookup.xlsx`, with forward-fill handling for merged-cell style source files
4. **Never drops data silently** — terminals with no matching prefix are kept and flagged as `UNKNOWN` instead of being discarded
5. **Applies a per-provider fee schedule** with a configurable default
6. **Exports a formatted Excel workbook** with a transaction detail sheet (frozen header, auto-filter, number formats) and a per-provider summary sheet

## Results

| | Manual process | This pipeline |
|---|---|---|
| Time per day | ~1–2 hours | < 1 minute |
| Missed records | Possible (silent) | Zero — unmatched rows flagged, never dropped |
| Format errors | Frequent | Eliminated by positional config |

## Quick Start

```bash
pip install openpyxl

# 1. Generate fictional sample data (3 days, 200 rows per file)
python generate_sample_data.py

# 2. Run the parser
python parse_transactions.py

# Output: sample_data/consolidated_report.xlsx
```

Options:

```bash
python generate_sample_data.py --days 7 --rows 500   # more sample data
python parse_transactions.py --rc all                # keep all response codes
python parse_transactions.py --input /path/to/files  # custom input folder
```

## Project Structure

```
transaction-report-parser/
├── parse_transactions.py      # main pipeline
├── generate_sample_data.py    # creates fictional input files
└── sample_data/               # generated at runtime (gitignored except lookup)
    ├── ALPHA_YYYYMMDD.raw     # pipe-delimited reports
    ├── BETA_YYMMDD.txt        # fixed-width reports
    ├── terminal_lookup.xlsx   # terminal prefix -> provider mapping
    └── consolidated_report.xlsx
```

## Tech Stack

- **Python 3.10+** — standard library only, plus `openpyxl` for Excel I/O
- Dataclass-based record model, config-driven fixed-width layout
- Designed to run unattended (e.g., via Windows Task Scheduler / cron)

## What This Demonstrates

- Parsing heterogeneous raw file formats (delimited and fixed-width positional)
- Defensive data handling: explicit filters, fallback flags, no silent drops
- Lookup-table enrichment with forward-fill for messy real-world source files
- Automated, professionally formatted Excel reporting with openpyxl
- Config-driven design: new networks can be added by defining a layout + reader
